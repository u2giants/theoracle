## Irreversible postseal prevention

After preload, install irreversible no_new_privs and ONE exact pinned classic-BPF seccomp program. Validate audit architecture x86_64, reject x32 and unknown ABI/syscalls, handle high argument words explicitly, then default-deny unlisted calls. No TRACE/USER_NOTIF/LOG/broker or fallback. Prevent new path reads/imports/dlopen/exec/network/processes/descriptor acquisition after seal. Deny ALL mprotect/pkey_mprotect/mremap, not only direct PROT_EXEC. Allow mmap only fixed demonstrated private anonymous non-executable allocations with exact required flags, no MAP_FIXED/SHARED/file backing/unknown flags and no READ_IMPLIES_EXEC. Reject inherited extra descriptors before seal; do not allow dup/FD replacement or SCM_RIGHTS. If existing parser needs a duplicated fd, create the exact bounded handle before seal and account for it in the fixed three-data-FD contract; do not quietly allow arbitrary dup.

Allow only necessary reads/pread/lseek/fstat against those exact read-only data descriptors; exact bounded stdout/private stderr writes; required fixed clocks/signals/futex/allocator/unmap/exit operations under reviewed argument constraints. Derive the finite allowlist from actual same parser and pinned supported interpreter behavior, then independently review it; no broad allowlist guessed from installed headers. Failure before/after seal or an unknown required syscall refuses; preserve the old capability, never silently revert to unsealed parsing.

Exact kernel-exported attached-BPF readback needs unavailable capability. Root proposes the following precise evidence model, NOT a claim of that unavailable export: trusted independently pinned bootstrap constructing pinned BPF bytes; actual successful irreversible installation; parent reads actual NNP1/Seccomp2/filter-count transition and exact supported closure/descriptor state before sending any archive bytes; later adversarial probes prove relevant denied syscall classes. Reviewer must reject this model if the original prevention requirement cannot be satisfied under the stated trusted-bootstrap/kernel model. No privilege acquisition or host-policy weakening is proposed.
