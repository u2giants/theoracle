# B1 — owner-approved question set (repair plan phase B)

Test evidence for [plan_oracle_repair_and_consultant_upgrade.md](../../../plan_oracle_repair_and_consultant_upgrade.md)
step B1 (issue #520). The drafts and their recommendations live on the
site's eval page (the owner's only review surface); this file holds counts,
the coverage table and gate proof only. Times are New York (EST/EDT).

## What landed

- SQL `apps/brain/brain/sql/019_eval_question_admin.sql` on `cmap.eval_question`
  (idempotent; `T/test_schema.py::test_migrate_runs_twice_without_error` green):
  - `approved_at timestamptz` — null = not yet approved; only approved
    questions count toward the eval bar.
  - `function text[]` — nullable, multi-valued (a question may span several
    functions); **left empty by B1, filled in step C1**.
  - `abstention boolean NOT NULL DEFAULT false` — marks the five "the
    documents do not say" questions; B2's scoring codes against this name.
  - `retired_at timestamptz` — null = active (no prior status convention
    existed on the table).
  - `recommendation text` — the admin's per-question note, rendered on the
    eval page for the owner.
- Admin API (`B/api/eval.py`): `POST /eval/questions/{id}/approve`,
  `PUT /eval/questions/{id}` (edit), `POST /eval/questions/{id}/retire` —
  all behind `require_admin`, like the rest of the eval endpoints.
- Eval runner (`B/eval/run.py`): `load_questions()` filters
  `approved_at IS NOT NULL AND retired_at IS NULL` — the only scored set.
- Eval page (`W/map/eval`): per-question Approve / Edit / Retire for admin,
  a status line per question (draft / approved / retired, New York time
  labelled EST/EDT), the recommendation badge and the abstention badge.
