## One original local STOP operation

The persistent STOP process uses one fixed no-argument local cycle. It captures
wall and monotonic clocks before configuration, profile, key, TLS or body reads.

chosen deadline string; it is never reformatted into a later deadline.

Before invitation, the independently installed margin must cover the maximum poll

The due time is `capture_until - margin`. If the queue read consumes the budget,
later stages refuse before credentials/body/claim where possible; a possibly

and spacing. A post-stop delay must fit the original remaining budget. No wait,
provider outage, body chunk or restart starts another window.

The scheduler and STOP service have distinct own-role supervision profiles. They
reuse the same bounded SQL connector and strict file/clock/TLS owners. Current SQL

## Actual receipts and uncertainty

Create, leave and the two independently installed retrieve stages are globally
once across admission/runtime generations. A lost or repeated executable claim
cannot return another request body. Worker local exclusive execution custody is
bound to the newly created file identity; an old same-operation receipt cannot be
reinterpreted as new execution after a path swap. Retained JSON/XML/request bodies
are evidence, never redispatch instructions.

Pre-stop GET proves only exact-bot consistency. A complete empty leave HTTP200 is
an acknowledgement, not remote-stop proof. An incomplete, delayed, extra, duplicate,
truncated or unclosed response is uncertain; it cannot trigger automatic POST
resend. The actual complete raw wire is retained before semantic interpretation.
Only the separately installed post-stop GET stage can support the existing SQL
STOP reconciliation, using the exact immutable receipt, actual response body hash,
exact bot and unambiguous latest nonfuture documented terminal status. There is no
status polling or replacement GET after an UNKNOWN attempt. Capture remains closed
whether STOP succeeds, fails, is cancelled or is unproved.

A complete authenticated Create receipt observed after cancellation/closure may
retain a forensic created-bot relation for independently installed STOP only.
It cannot reopen capture, learning, ingress, Create, bot mapping or source rights.
Partial wire or caller-supplied bot/status labels cannot create that relation.
A provider acknowledgement or public webhook acknowledgement is not evidence that
the remote effect stopped or that an internal worker ran.
